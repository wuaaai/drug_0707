## Summary

TrajectoryCare 回答一个科学问题：**疾病演化轨迹能否替代静态疾病分类，成为混合专家（MoE）模型专家划分的组织原则？**

现有 MoE 用 ICD 章节定义专家——"循环系统专家处理所有 I 开头的编码"。但这忽略了一个临床事实：同一个 I50（心力衰竭），因来自十年高血压的代偿耗竭还是急性心梗的心肌坏死，其预后、治疗和风险模式截然不同。**按"得了什么病"划分专家，无法区分"同病不同径"。**

TrajectoryCare 提出**按"病是怎么来的"划分专家**——从 EHR 纵向诊断序列中无监督发现疾病演化原型（如"代谢→心肾进行性损伤"、"感染→全身炎症→器官衰竭"），将每个原型实例化为一个 MoE 专家。核心假说：轨迹驱动的专家划分优于静态知识驱动的划分。

## Scientific Problem

### 核心科学问题

**疾病演化轨迹能否作为 MoE 专家划分的组织原则？**

这一问题的科学意义在于：如果答案是肯定的，则意味着模型架构的设计原则从"按疾病分类学组织参数"转变为"按病理演化路径组织参数"——这是从静态本体论到动态过程论的范式转换。

### 三个可验证的子问题

- **SQ1（可发现性）**：从纵向 EHR 中能否无监督地发现具有明确病理语义的疾病演化原型？
- **SQ2（有效性）**：轨迹驱动的专家划分在临床预测任务上是否优于 ICD 章节驱动的专家划分？
- **SQ3（差异化处理）**：同一诊断编码在不同演化路径下，是否确实被不同专家差异化处理且处理方式合理？

### 为什么现有方法无法回答

| 方法范式 | 专家定义原则 | 为何不充分 |
|----------|-------------|-----------|
| 标准 MoE (Shazeer 2017) | 数据统计聚类 | 专家无语义，无法解释 |
| ExpertCare | ICD 静态分类树 | 同病同专家，忽视演化路径 |
| DynMoE (2025) | 训练中动态增减 | 专家仍是无医学语义的参数块 |
| I2MoE (2025) | 模态交互模式 | 按数据类型分专家，非按病理 |

这些方法的共同局限：专家的定义与疾病演化无关。所有告诉我们轨迹有预测价值的文献（Jensen, Beck, Siggaard），其产出的轨迹从未进入模型架构内部成为参数组织的原则。

## Core Hypothesis & Claims

**H1（主假说）**：从纵向 EHR 中无监督发现的疾病演化原型可以实例化为 MoE 专家，且这些专家在临床预测任务上的性能优于基于 ICD 静态分类的专家划分。

**Claim 1（原型可发现性）**：ICD 章节块级别的纵向转移模式可以聚类为数量有限、病理语义明确的轨迹原型。对应 SQ1。

**Claim 2（路由有效性）**：基于患者历史章节块序列的路由器可以将患者分配到正确的轨迹专家，且路由分配随疾病进展动态演化。对应 SQ2。

**Claim 3（差异化处理）**：同一诊断编码（如 I50）在不同轨迹原型中被不同专家处理后，其内部表示和预测输出存在可解释的差异——反映了不同演化路径下的不同临床逻辑。对应 SQ3。

## Method Overview

核心方法分三步，每一步只做一件事：

```
ICD 编码序列 → [1. 空间降维] → 章节块序列
                → [2. 轨迹抽象] → K 个轨迹原型
                → [3. 轨迹驱动 MoE] → 预测输出
```

### Step 1: 空间降维（ICD → 章节块）

将数百种 ICD 编码归约到 19/23 个章节块。目的：克服高维稀疏性，使轨迹模式在可控维度上可计算。这本身不是创新——创新在于后续用这些块序列来定义专家。

### Step 2: 轨迹抽象（章节块序列 → 轨迹原型）

核心思路：构建章节块级有向转移图，在图拓扑空间中聚类出轨迹原型。

具体做法：构建非对称转移矩阵（A_ij ≠ A_ji，区分"A→B"与"B→A"的转移强度差异），在此矩阵定义的转移空间中，将具有相似入边/出边分布模式的章节块合并为轨迹原型。聚类数 K 通过轮廓系数确定。

方法选择原则：我们选择**图拓扑聚类**而非更复杂的序列编码（如 Transformer 嵌入），因为这一步的目标不是"最好的聚类"，而是"可解释的原型"——图的节点和边本身就是人类可读的（"C4→C9→C14"），不需要解码器来解释嵌入空间。

### Step 3: 轨迹驱动 MoE

**专家实例化**：K 个轨迹原型 → K 个专家子网络。每个专家内部包含 GRU 时序编码器，参数独立。不同轨迹原型下的疾病进展节奏不同（慢性的代偿耗竭 vs. 急性的打击），独立的 GRU 允许专家学习轨迹特定的时序动态。

**路由器设计**：给定患者的历史章节块序列，计算其转移模式与各轨迹原型的匹配分数。核心设计选择：使用**软路由**（所有专家输出的加权和，权重 = softmax(匹配分数)）而非硬路由（top-1）。理由：患者可以同时走在多条轨迹上（如既有代谢基础病又有急性感染），硬路由强行二选一丢失信息。

**时序条件化**：专家内部的 GRU 不仅接收诊断/手术/药物的嵌入，还接收就诊内检验异常的聚合信号——检验异常的模式反映了患者在该轨迹上的当前阶段（早期代偿 vs. 晚期失代偿）。

## Requirements

### Core（必须验证的假说）

- R1. 在 MIMIC-III 和 MIMIC-IV 上，轨迹驱动 MoE 在药物推荐和诊断预测任务上的性能显著优于 ExpertCare（ICD 静态专家划分）。
- R2. 发现的轨迹原型具有可解释的病理语义——每个原型可被人类医生用一句话描述（如"代谢→心肾进行性损伤"）。
- R3. 同一诊断编码在不同轨迹原型中被不同专家处理时，其内部表示和预测输出存在显著且可解释的差异。

### Engineering（支撑核心验证）

- R4. ICD→章节块映射 + 块级序列构建。
- R5. 轨迹原型发现：转移图构建 + 图拓扑聚类 + K 自动确定。
- R6. 轨迹驱动 MoE：K 个 GRU 专家 + 软路由器 + 检验信号条件化。
- R7. 对比基线：ExpertCare + GRU + Transformer + RETAIN + StageNet + KAME。
- R8. 消融：移除轨迹路由（统一模型）、替换为 ICD 章节路由（退化为 ExpertCare）。
- R9. 冷启动处理：单次就诊患者使用章节分布先验 + 均匀退火。
- R10. 时间因果性：visit t 的预测仅使用 ≤ t-1 的历史。

## Key Technical Decisions

- **图拓扑聚类而非序列深度编码。** 轨迹发现的目标是可解释性，不是聚类精度。图拓扑（节点=章节块，边=转移概率）天然可读，不需要解码器。如果追求"最好的聚类"而使用权值不可解释的深度编码器，Claim 1 无法验证。

- **软路由而非硬路由。** 患者可同时属于多个轨迹（如慢性代谢病 + 急性感染），软路由允许加权混合，硬路由强制二选一。这更符合临床实际，且避免了硬路由的训练不稳定问题。

- **从参考文献中借鉴的有限技术**——只取直接服务于三个 Claims 验证的：
  - 非对称转移矩阵 + 图拓扑聚类的具体实现借鉴 tphenotype 的 GraphKmeans（路径一致性检验天然适合轨迹相似度度量）。
  - DDI 约束通过 subtractive GCN 内化到药物嵌入（借鉴 COGNet 的设计，但这是工程优化，不是核心创新）。
  - 冷启动退火路由（温度随就诊数衰减），因为冷启动患者无法验证 Claim 2。
  - *不引入*：因果发现（Claim 本身不依赖因果验证）、动态原型微调（先验证固定原型有效再加）、跨患者检索（增加复杂度但不改变结论）。

## Implementation Units

### U1. ICD 章节映射与块级序列构建

- **Goal:** 建立 ICD→章节块映射，为所有患者构建块级纵向序列。
- **Requirements:** R4
- **Files:** `preprocess/icd_chapter_mapping.py`（新建）、`preprocess/trajectory_data_builder.py`（新建）
- **Approach:** ICD-9/10 前三位→章节块。输出 visit 级章节列表 `[[C9, C4], [C9, C14], ...]`。同时统计章节间非对称转移频次矩阵。
- **Test scenarios:** I10→C9, E11→C4 映射正确；同 visit 多诊断→多章节；空序列→空列表。
- **Verification:** 高频转移（C4→C9, C9→C14）符合临床预期。

### U2. 轨迹原型发现

- **Goal:** 从块级序列中无监督发现 K 个轨迹原型，每个具有可解释的病理语义。
- **Requirements:** R5, R2
- **Files:** `models/trajectory_mining/` 目录（`transition_graph.py`, `topology_clustering.py`, `prototype_discovery.py`）
- **Approach:** (1) 构建非对称有向转移图（A_ij = P(块_j | 块_i)），(2) 在转移空间中计算节点的入边/出边分布特征作为节点表示，(3) 用 GraphKmeans（借鉴 tphenotype 的路径一致性检验）聚类，K 通过轮廓系数确定，(4) 导出原型 JSON（ID、典型章节块集合、代表性转移路径、簇内患者数）。谱聚类作为简单基线。
- **Test scenarios:** K ∈ [4,12]；每个原型 ≥ 2 个典型块；两次运行产生一致分配。
- **Verification:** 人工判断每个原型的临床可解释性。Claim 1 的验证依据。

### U3. 轨迹驱动 MoE 模型

- **Goal:** 实现完整的 TrajectoryCare 模型：K 个轨迹专家 + 软路由器 + 时序条件化。
- **Requirements:** R6, R9, R10
- **Dependencies:** U2
- **Files:** `models/TrajectoryCare.py`, `models/moe/router.py`, `models/moe/experts.py`, `models/moe/cold_start.py`
- **Approach:** 路由器计算患者历史块序列与各轨迹原型的软匹配分数（考虑入边/出边分布相似度）。K 个专家 = K 个独立 GRU 编码器（复用 Base2_1 结构）。专家输入：历史诊断/手术/药物嵌入 + 检验异常聚合信号。输出 = Σ softmax(匹配分数)_i * expert_i(hidden)。冷启动（< 2 visits）：章节分布先验 + 均匀退火。时间因果性：路由仅用 ≤ t-1 历史。
- **Test scenarios:** 路由分数随轨迹变化；冷启动患者路由接近均匀；输出形状兼容现有训练代码。
- **Verification:** 模拟 3 条典型轨迹各 100 患者，路由热图验证同轨迹患者→同专家。Claim 2 和 Claim 3 的验证依据。

### U4. DDI 感知药物编码器（工程支撑）

- **Goal:** 将 DDI 知识融入药物嵌入，为所有专家提供 DDI-aware 的药物表示。
- **Requirements:** 无独立的假说验证需求
- **Files:** `models/ddi_encoder.py`
- **Approach:** subtractive GCN：`drug_memory = ehr_gcn - inter * ddi_gcn`。可选的 DDI 辅助损失。这是工程优化，不被列为独立的科学贡献。

### U5. 训练集成与实验评估

- **Goal:** 集成到现有训练流程，运行主实验 + 消融 + 可解释性分析。
- **Requirements:** R1, R3, R7, R8
- **Dependencies:** U3, U4
- **Files:** `main.py`（修改）、`trainer.py`（修改）、`analysis/trajectory_care_eval.py`（新建）、`analysis/ablation.py`（新建）、`analysis/interpretability.py`（新建）
- **Approach:** 三个实验块。(1) 主实验：MIMIC-III + MIMIC-IV × drug_rec + diag_pred × TrajectoryCare + 6 baselines，5 seeds。(2) 消融：移除轨迹路由（统一模型）、替换为 ICD 章节路由（退化为 ExpertCare 等价物）——后者是最关键的消融，直接验证核心假说。(3) Claim 3 验证：选取心衰 I50 患者，分出高血压→心衰 vs. 心梗→心衰两条路径，比较两组在不同专家下的表示差异和预测差异。
- **Test scenarios:** TrajectoryCare > ExpertCare (p < 0.05)；ICD 路由消融不优于轨迹路由；I50 两路径组在专家分配上显著不同。
- **Verification:** 生成实验表格 + 路由热图 + Case Study 可视化。三个 Claims 的完整验证。

## Scope Boundaries

**这是核心创新：** 用轨迹原型定义 MoE 专家，证明它优于静态 ICD 分类定义。以下不在本次范围内：
- 端到端学习轨迹原型（先证明预计算原型有效，再考虑可微化）
- DDI 分子子结构建模（工程增强，等核心假说验证后加）
- 多模态数据融合（影像、文本）
- 动态增删专家（DynMoE 路线——我们的专家是语义定义的，不是算力优化的）

## Open Questions

- 轨迹原型的临床可解释性需要医生合作验证——当前用人工判断替代，正式投稿前需临床合作者盲审。
- K 的自动确定依赖轮廓系数，可能给出与临床直觉不一致的值——约定临床可解释性优先。

## Risks

- **原型不可解释**：聚类结果无清晰病理语义 → Claim 1 失败。缓解：降回 ICD 章节块级解释（"此原型主要覆盖 C4+C9+C14"），即使不能命名也能定量分析。
- **性能不显著优于 ExpertCare**：→ 核心假说被证伪。这本身也是科学贡献（证明轨迹驱动不比静态分类驱动好），但论文叙事需调整。缓解：先在小规模 MIMIC-III 上跑 pilot，确认正信号再完整实验。
- **路由坍缩**：所有患者路由到同一专家 → 等价于无 MoE。缓解：软路由 + 熵正则化。
